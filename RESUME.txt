6. HOUSE RULES THE NEXT SESSION MUST NOT BREAK
====================================================================

  * NO "Co-Authored-By: Claude" OR "Claude-Session:" TRAILERS in commit
    messages. Ashutosh Sinha is the sole author. Absolute.
  * git add with EXPLICIT PATHS. Never git add -A.
  * The drill after every piece of work: verify, commit, push develop,
    then fast-forward main:
        git push origin develop && git push origin develop:main
  * docs/qa/FINDINGS.md is owned by the lead. Agents must never edit it.
  * Documentation rot is a build failure here. DocumentationFreshness-
    Test and FindingsRegisterTest enforce it. Run them after doc edits:
        ./mvnw -o -pl pravaha-it test \
          -Dtest='DocumentationFreshnessTest,FindingsRegisterTest' \
          -DfailIfNoSpecifiedTests=false
  * Publish a status update roughly every 10 minutes during long runs.
  * NEVER report a build as passing without checking. Grep for
    BUILD SUCCESS and BUILD FAILURE separately and report both counts.
    A zero exit code from a piped command is NOT proof -- this has
    produced false "clean" reports more than once.
  * Do NOT run two Maven builds in the same checkout at once; they
    corrupt each other's target/. Concurrent agents need worktrees.
