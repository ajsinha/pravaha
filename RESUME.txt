====================================================================

           main", so between drills it is BEHIND develop. That is intended.

  Findings register: 0 GA-BLOCKER, 0 GA-REQUIRED. The header of
  docs/qa/FINDINGS.md has the exact counts and FindingsRegisterTest holds it
  to them.

  S-3 was reopened and re-fixed on 2026-09-19. 9238785 had removed
  CoordinatorFactory's refusal of PARTITIONED while nothing in a node consumed
  partition ownership. The refusal now lives in PravahaNode
  (refusePartitionedServing, PRV-9002): the factory still builds the
  coordinator, so membership/assignment/leases stay testable as a library,
  and a node will not serve PARTITIONED. Whoever builds ADR-039 item 8's
  consumer removes that refusal in the same change.

  An agent had started that consumer in
  .claude/worktrees/agent-a15965300af1b29ea, as UNCOMMITTED edits: a per-row
  ownership gate in PartitionedIngestPump that DROPS rows this node cannot
  prove it owns. Review the design before using it: dropping is only safe if
  another node reads the same source and keeps the row; otherwise, once the
  offset moves past it, the row is lost.

====================================================================

    supports it (QueryRegistry.multiplexingLanes); PravahaNode never calls it,
    and there is no admission control. Note there is NO pravaha.lane.multiplex

  - Item 5 follow-ups: aerospike-sink (upsert + delete, composite keys) is

    not record the sink.

  - Item 7: console design-system surface, not built by decision.
  - Item 8: cluster mode -- the runtime consumer of ownership, then rebalance.

4. HOUSE RULES
====================================================================

  * NO "Co-Authored-By: Claude" OR "Claude-Session:" TRAILERS in commit
    messages. Ashutosh Sinha is the sole author. Absolute.
  * git add with EXPLICIT PATHS. Never git add -A.
  * Verify, THEN commit, THEN push. "Drill to develop" = commit and push
    develop. "Drill to main" = merge develop into main and push main. A bare
    "drill" = both. Work happens on develop; main moves only on a drill.
  * docs/qa/FINDINGS.md is owned by the lead session. Agents never edit it.
  * Documentation rot is a build failure. After doc edits:
        ./mvnw -o -pl pravaha-it test \
          -Dtest='DocumentationFreshnessTest,FindingsRegisterTest' \
          -DfailIfNoSpecifiedTests=false
  * NEVER report a build as passing without checking. Grep for BUILD SUCCESS
    and BUILD FAILURE separately and report both counts. A run with
    -Dmaven.test.failure.ignore prints BUILD SUCCESS over failing tests.
  * Do NOT run two Maven builds in the same checkout at once.
  * Avoid SQL reserved words as test view names: second, large, and friends
    are refused with PRV-8008.
